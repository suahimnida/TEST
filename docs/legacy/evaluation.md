# ML 모델 평가 보고서

## 1. 결론 요약

- 내부 평가(학습 데이터를 나눈 평가)에서는 오탐률 0.29%, 미탐률 2.17%로 매우 좋아 보인다.
- 학습에 없던 외부 평가 세트에서는 **정상 URL의 80%를 피싱으로 판정**했다 (60점 기준).
- 원인은 데이터셋 편향이다. 학습 데이터의 정상 URL은 100% `https://www.도메인` 형태이고 경로가 없다.
  모델은 피싱의 특징이 아니라 "`https://www.`로 시작하고 경로가 없으면 정상"이라는 지름길을 배웠다.
  - 이 규칙 하나만으로 내부 평가 정확도가 99.53%로, 모델(98.87%)보다 높다.
  - 외부 평가에서 모델과 이 규칙의 판정이 99.83% 일치한다.
- 따라서 지금 모델의 내부 정확도 98.87%는 피싱 탐지 능력을 보여 주지 않는다. 모델 재학습이 필요하다.
- **재학습 결과 (7장):** 편향을 고친 데이터로 다시 학습한 새 모델은 외부 오탐률을 80.2%에서 34.2%로 줄였고, 허용 목록까지 적용한 서비스 전체 오탐률은 2.0%다 (허용 목록 효과는 낙관적인 값). 대신 미탐률은 0.1%에서 13.3%로 올랐다.

## 2. 평가 방법

### 지표
정확도 대신 혼동 행렬로 보고한다.

| | 모델: 피싱 | 모델: 정상 |
|---|---|---|
| 실제 피싱 | 정탐 (TP) | 미탐 (FN) |
| 실제 정상 | 오탐 (FP) | 정상 통과 (TN) |

- 오탐률 = FP ÷ (FP + TN): 정상 사이트를 잘못 경고하는 비율
- 미탐률 = FN ÷ (FN + TP): 피싱을 놓치는 비율
- 서비스 화면 기준에 맞춰 30점(의심), 50점(모델 기본), 60점(피싱 판정) 세 기준에서 계산한다.

### 내부 평가 세트
`scripts/train_model.py`와 같은 방식(PhiUSIIL, test_size=0.2, random_state=42, 라벨 비율 유지)으로 나눈 47,159건.

### 외부 평가 세트 (`evaluation/eval_set.csv`)
| 구분 | 건수 | 출처와 조건 |
|---|---|---|
| 피싱 | 2,000 | KISA 2023 피싱 사이트 목록. 2024 블랙리스트에 있는 URL(블랙리스트에 걸리면 ML을 거치지 않음)과 학습 데이터에 있던 도메인은 제외. 한 캠페인이 결과를 좌우하지 않도록 등록 도메인당 최대 3건 (1,207개 도메인) |
| 정상 | 409 | 국내외 정상 서비스 82개 도메인을 `https://www.`, `https://`, `http://`, scheme 없음 4가지 형태로 변형 + 경로가 있는 정상 URL 81개 (로그인 페이지 포함) |

- URL은 원문 그대로 평가한다.
- 정상 URL 중 106건은 학습 데이터에 있던 도메인(`naver.com` 등)이라, 학습에 없던 도메인만 따로 계산한 결과도 함께 낸다.
- 경로 속 게시글·상품 번호는 실제 서비스의 주소 형태를 따른 예시다. 모델은 접속하지 않고 문자열만 보므로 번호의 실제 존재 여부는 결과에 영향이 없다.

## 3. 결과

### 내부 평가 vs 외부 평가 (60점 기준)

| 평가 세트 | 오탐률 | 미탐률 | ROC-AUC |
|---|---|---|---|
| 내부 (PhiUSIIL) | **0.29%** | 2.17% | 0.9989 |
| 외부 | **80.2%** | 0.10% | 0.39 |
| 외부 (학습에 없던 도메인만) | 79.9% | 0.10% | 0.40 |

외부 평가의 정확도는 86.3%로 나오는데, 피싱이 정상보다 5배 많아서 생긴 숫자다. 정확도만 봤다면 "괜찮은 모델"로 오해했을 것이다.

ROC-AUC가 0.5보다 낮다는 것은 평균적으로 정상 URL에 피싱보다 높은 점수를 줬다는 뜻이다. 경로가 있는 정상 URL은 평균 99.9점, 피싱은 평균 약 95점이었다.

### 지름길 규칙과의 비교

"`https://www.`로 시작하고 경로가 없으면 정상, 아니면 피싱"이라는 규칙 하나와 비교했다.

| | 내부 평가 정확도 | 외부 평가 오탐률 | 외부 평가 미탐률 |
|---|---|---|---|
| ML 모델 (50점) | 98.87% | 80.4% | 0.10% |
| 지름길 규칙 | **99.53%** | 80.0% | 0.20% |

모델의 특징 중요도 상위도 경로 길이(0.185), URL 길이(0.178), www 개수(0.148), 도메인 길이(0.134) 순으로, 이 규칙과 같은 정보에 의존한다.

| 기타 | 1 | `https://www.11st.co.kr` (도메인에 숫자) |

### 미탐 2건 (피싱을 정상으로)

| URL | 점수 | 이유 |
|---|---|---|
| `https://www.ilogenst.com` | 7.3 | 택배사 도메인과 철자가 비슷한 짧은 도메인을 `https://www.` 형태로 사용 |
| `https://www.ilogens.com` | 7.5 | 같은 캠페인 |

### URL만으로 판단하기 어려운 이유

1. **학습 데이터 편향** (데이터로 해결 가능): 정상 URL이 모두 같은 형태라 모델이 형태를 외웠다. 형태가 다양한 정상 URL을 학습에 넣으면 줄일 수 있다.
2. **정상 서비스도 피싱과 같은 단어를 쓴다**: 실제 로그인 페이지는 `login`, `account`, `signin`을 포함한다. 키워드만으로는 진짜 로그인 페이지와 가짜를 구분할 수 없고, 공식 도메인인지가 핵심이다.
3. **철자가 비슷한 도메인**: `ilogenst.com` 같은 도메인은 의심 특징(키워드, IP, 긴 길이)이 없다. 공식 도메인 목록과의 철자 유사도나 도메인 등록일 같은 다른 신호가 필요하다.
4. **같은 형태를 정상과 피싱이 함께 쓴다**: 무료 호스팅 하위 도메인(`*.vercel.app`, `*.web.app`)과 단축 URL은 정상 서비스도 쓰기 때문에 형태만으로는 구분이 어렵다.

## 5. 이 평가의 한계

- 정상 URL 409건은 직접 고른 목록이라 규모가 작다. Tranco 상위 사이트 목록을 `--tranco`로 추가하면 늘릴 수 있다.
- KISA 2023 피싱 URL은 경로가 거의 없고(3%) 대부분 무작위 하위 도메인 형태라, 경로를 쓰는 피싱(해킹당한 사이트 아래 숨긴 페이지 등)에 대한 미탐률은 이 평가로 알 수 없다.
- 평가 세트의 정상과 피싱은 출처가 다르다. 출처 차이 자체를 모델이 구분할 위험이 있으므로, 재학습 후에는 같은 출처에서 정상·피싱을 함께 모은 데이터로도 확인해야 한다.

## 6. 다음 단계

1. 학습 데이터 보강: `http://`, www 없는 주소, 경로가 있는 정상 URL, 정상 서비스의 로그인 URL을 추가한다.
2. 문자 n-gram 모델을 기준선으로 만들고, 구조 특징(scheme·host·path·query 분리)과 엔트로피를 하나씩 더하며 이 평가 세트로 비교한다.
3. 매 단계마다 지름길 규칙보다 나은지 확인한다. 외부 평가에서 지름길 규칙을 이기지 못하면 모델이 편향을 다시 배운 것이다.
4. 공식 도메인 허용 목록과 철자 유사도 탐지를 별도 근거로 추가한다.

## 7. 모델 v2: 편향을 고친 데이터로 다시 학습

### 무엇을 바꿨나
- **전처리** (`backend/ml_integration/url_features.py`): URL 원문을 바꾸지 않고 scheme·host·path·query로 나눈다. scheme과 www 유무는 지름길이 되므로 특징으로 쓰지 않는다.
- **학습 데이터** (`scripts/build_training_set.py`): PhiUSIIL에 경로가 있는 정상·피싱 URL(공개 URL 데이터셋)과 KISA 2024 피싱을 더하고, 정상·피싱 모두에 scheme과 www를 같은 확률로 무작위로 바꿔 형태만으로는 정답을 알 수 없게 했다. 외부 평가 세트의 도메인은 학습에서 모두 뺐다.

| | scheme (https/http/없음) | www | 경로 있음 |
|---|---|---|---|
| 기존 정상 데이터 | 100% / 0 / 0 | 100% | 0% |
| 새 정상 데이터 | 45% / 25% / 30% | 38% | 38% |
| 새 피싱 데이터 | 45% / 25% / 30% | 30% | 36% |

### 단계별 비교 (`scripts/train_url_model.py`, 결과: `evaluation/results/ablation.md`)
검증 세트는 학습 데이터에서 도메인 단위로 떼어 낸 38,344건(50점 기준), 외부는 60점 기준이다.

| 모델 | 검증 ROC-AUC | 외부 ROC-AUC | 외부 오탐률 | 외부 미탐률 | 외부 오탐률 (https://www 홈페이지 / 그 외) |
|---|---|---|---|---|---|
| 기존 서비스 모델 (랜덤 포레스트) | 0.47 | 0.39 | 80.2% | 0.1% | 1% / 100% |
| S1-편향: 문자 n-gram + 기존 데이터 | 0.56 | 0.77 | 75.6% | 0.8% | 0% / 94.5% |
| S1: 문자 n-gram + 새 데이터 | 0.930 | 0.867 | 51.8% | 4.9% | 41% / 54% |
| S2: + 정규화 | 0.930 | 0.874 | 51.1% | 6.3% | 48% / 52% |
| S3: + 구조 분리 (host·path) | 0.928 | 0.897 | 49.6% | 4.4% | 46% / 50% |
| S4: + 구조 특징 | 0.931 | 0.941 | 46.0% | 2.2% | 41% / 47% |
| S5a: + 도메인 엔트로피 | 0.931 | 0.941 | 45.7% | 2.2% | 41% / 47% |
| S5b: + 엔트로피 3개 | 0.935 | 0.932 | 44.3% | 2.9% | 40% / 45% |

알게 된 것
1. **원인은 모델 종류가 아니라 데이터였다.** 문자 n-gram도 기존 데이터로 학습하면 똑같이 "https://www.이면 정상"을 배웠다 (0% / 94.5%).
2. **새 데이터로 지름길이 사라졌다.** 형태별 오탐률 차이가 1% / 100%에서 41% / 54%로 줄었고 외부 ROC-AUC가 0.39에서 0.87~0.94로 올랐다.
3. **구조 특징은 학습에 없던 데이터에서 효과가 크다.** 검증 성능은 거의 같지만 외부 ROC-AUC가 0.87(S1)에서 0.94(S4)로 올랐다. 검증 세트는 학습 데이터와 분포가 같아서 이 차이를 보여 주지 못한다.
4. **엔트로피는 하나면 충분하다.** 3개를 넣은 S5b는 검증 성능은 오르지만 외부 성능은 떨어졌다. 학습 데이터에만 맞춰지는 현상이다.

### 모델 선택과 기준점
- 선택 규칙(미리 정함): 검증 ROC-AUC가 최고(0.9347)와 0.005 이내인 단계 중 가장 단순한 단계 → **S1**. 외부 결과를 보고 S4로 바꾸면 외부 평가 세트가 더 이상 공정한 시험이 아니게 되므로 규칙을 따랐다. S4가 외부 성능은 더 좋으므로, 새로운 외부 데이터로 다시 확인한 뒤 `--choose S4`로 바꾸는 것을 권장한다.
- 기준점: 검증 세트 오탐률 5% 이하가 되는 점수를 "의심(30점)", 2% 이하가 되는 점수를 "피싱(60점)"으로 맞추도록 점수를 변환했다 (순서는 그대로).

### 최종 결과 (외부 평가, 60점 기준)
| | 오탐률 | 미탐률 |
|---|---|---|
| 기존 서비스 모델 | 80.2% | 0.1% |
| 새 모델 단독 (S1 + 기준점 보정) | 34.2% | 13.3% |
| 참고: S4 + 기준점 보정 | 24.5% | 7.0% |
| 서비스 전체 (새 모델 + 허용 목록) | 2.0% | 13.3% |

- **허용 목록 효과는 낙관적이다.** 평가 세트의 정상 URL은 유명 서비스 위주라 81%가 허용 목록에 들어 있다. 덜 유명한 정상 사이트에는 적용되지 않으므로 모델 단독 성능이 더 현실적인 기준이다. 피싱 URL은 허용 목록과 하나도 겹치지 않았다.
- 미탐률은 0.1%에서 13.3%로 올랐다. 기존 모델은 거의 모든 URL을 피싱이라고 해서 미탐이 적었던 것이다.

### 허용 목록 (`backend/app/services/allowlist.py`)
- 목록: Moz Top 500(npm `top-sites`, MIT) + 국내 주요 서비스 52개 = 501개 도메인 (`scripts/build_allowlist.py`, `--tranco`로 Tranco 목록 추가 가능)
- 목록에 있으면 최종 위험도를 25점(정상)으로 제한한다. KISA 블랙리스트에 있으면 블랙리스트가 우선한다.
- 누구나 페이지를 올릴 수 있는 곳(`sites.google.com`, `docs.google.com`, `*.blogspot.com`, `*.github.io`, `*.vercel.app` 등)은 항상 제외한다.

### 남은 한계
- 공식 서비스의 진짜 로그인 페이지(`accounts.kakao.com/login` 등)는 URL만으로 피싱과 구분되지 않는다. 허용 목록 밖의 공식 사이트는 여전히 오탐이 난다.
- 국내 주요 서비스 목록은 직접 고른 것이라 외부 평가 세트의 국내 정상 도메인과 겹친다.
- 공개 URL 데이터셋은 오래됐고 라벨 오류가 있을 수 있다.

## 8. 평판 신호 (참고 근거)

사이트에 접속하지 않고 얻을 수 있는 도메인 정보를 "평판 신호"로 탐지 결과와 리포트에 보여 준다 (`backend/app/services/reputation.py`). **최종 점수에는 반영하지 않는다.**

| 신호 | 조회 방법 | 의심 근거로 표시하는 경우 |
|---|---|---|
| 도메인 등록일 | IANA 안내 목록 → TLD의 RDAP 서버 | 등록 30일 이내 |
| 인증서 첫 발급일 | 인증서 투명성 로그 검색(crt.sh) | 첫 인증서 30일 이내 |
| 호스팅 정보 | DNS-over-HTTPS로 IP → Team Cymru DNS로 ASN | DNS에 도메인이 없음 (호스팅 업체는 정보로만 표시) |

- 분석 대상 사이트의 웹 서버에는 연결하지 않고, 외부 서비스에는 도메인 이름만 보낸다 (경로·쿼리 제외). 도메인의 DNS 서버를 공격자가 운영하면 "조회했다"는 흔적은 남을 수 있다.
- 세 조회는 RAG와 동시에 실행하고, 각각 4초 제한을 둔다. 실패하면 "확인 불가"로 표시하고 분석은 계속한다. 결과는 도메인별로 하루 동안 캐시한다.
- `github.io`처럼 누구나 하위 주소를 만드는 서비스는 플랫폼 자체의 등록일이 의미가 없으므로 등록일과 인증서를 보지 않는다.
- RDAP를 지원하지 않는 TLD는 "확인 불가"로 표시한다.
- **호스팅 업체를 짐작으로 위험하다고 표시하지 않는다.** 수집 데이터에서 피싱 비율이 실제로 높은 업체가 확인될 때만 근거로 쓴다.

### 평가 방법 (점수 반영 전 필수)
지금 외부 평가 세트의 피싱(KISA 2023)은 3년 전 목록이라, 지금 조회하면 만료되거나 다시 등록된 도메인 정보가 나와 결과가 왜곡된다. 그래서 `scripts/collect_reputation.py`로 **새로 발견된 피싱 URL을 그날 바로 조회해 쌓는다.**

1. 1~2주 동안 매일 `python scripts/collect_reputation.py collect` 실행 (정상 쪽은 `--legit-file`로 덜 유명한 사이트를 함께 넣는다. 유명 사이트만 쓰면 "정상은 모두 오래된 도메인"이 되어 효과가 과장된다)
2. `python scripts/collect_reputation.py summarize`로 신호별 피싱·정상 비율 비교
3. 효과가 큰 신호만 ML 점수와 결합해 1장의 방식(오탐률·미탐률, 학습에 없던 데이터)으로 비교하고, 나아질 때만 점수에 반영한다.

## 9. 분석 범위와 페이지 내용

### 분석 범위를 화면에 밝힌다
결과 화면 맨 위에 "URL 문자열과 공개된 등록 정보(KISA 블랙리스트, 도메인 등록일, 인증서 기록, 호스팅 정보)만 확인했고, 이 사이트에는 접속하지 않았으며 페이지 내용(HTML, 텍스트, 이미지)은 확인하지 않았다"는 안내를 결과보다 먼저 보여 준다.

HTML·이미지를 분석하는 것처럼 보이던 문구를 실제 동작에 맞게 고쳤다.

| 화면 | 이전 | 이후 |
|---|---|---|
| 분석 중 화면 | URL 구조 → URL 통계 → 도메인(인증서·리디렉션) → HTML 분석 → 페이지 콘텐츠 → AI Agent | KISA 블랙리스트 → URL 구조 → ML 판정 → 평판 신호 → 유사 사례·AI 설명 |
| 대시보드 | "웹페이지 분석: HTML, 텍스트 및 이미지 요소를 분석" / "AI가 판단" | "평판 신호" / "AI 설명" |
| 탐지 방법 | 웹페이지 분석(HTML/DOM, 이미지) / AI가 위험도 판단 | 판정 반영(블랙리스트, ML)과 참고(URL 구조, 평판 신호, AI 설명)를 구분하고, 페이지 내용은 분석하지 않는다고 명시 |
| 결과 화면 탐지 결과 | "HTML 분석", "페이지 콘텐츠" 항목 (분석되지 않음) | 항목 없음 (예전 기록에 남은 항목도 표시하지 않음) |
| ML 모델 | URL 길이·엔트로피 등 특징, PhiUSIIL | 문자 n-gram(v2), 학습 데이터 3종, "학습에서 뺀 것" 설명 |

### 학습에서 HTML 특징을 쓰지 않았다
PhiUSIIL에는 HTML 기반 열이 있지만, 기존 모델(랜덤 포레스트)은 URL에서 계산한 21개 특징(`feature_columns.json`)만, 새 모델(v2)은 URL 원문의 문자 n-gram만 쓴다. 실제 분석 때 사이트에 접속하지 않으므로 HTML 특징은 만들 수 없고, 학습에서도 쓰지 않았다.

### 접속 없이 잡는 해킹 사이트 경로 패턴 (참고 근거)
해킹당한 정상 사이트에 숨긴 피싱 페이지의 경로 형태를 URL 구조 탐지에 추가했다.

| 패턴 | 예 |
|---|---|
| 관리용 폴더(`wp-content`, `wp-includes`, `.well-known`, `cgi-bin` 등) 아래 로그인·인증 단어 | `/wp-content/uploads/verify/login.php` |
| 관리 화면 폴더(`wp-admin` 등) 아래 다른 브랜드 이름 | `/wp-admin/includes/paypal/` |
| 경로에 다른 브랜드 이름 + 로그인·인증 단어 (공식 도메인이 아닐 때) | `random-shop.com/paypal/signin` |
| 경로 안에 다른 공식 도메인 | `/www.naver.com/login/` |

워드프레스 자체 관리자 로그인(`/wp-login.php`, `/wp-admin/`)은 정상 사이트에도 있어 그 자체로는 의심하지 않는다. 단어는 단어 단위로 비교한다(`accounting`을 `account`로 보지 않음).

| 데이터 | 건수 | 잡힘 |
|---|---|---|
| 정상: 공개 URL 데이터셋 (경로 있음) | 80,000 | 0 (0%) |
| 정상: 외부 평가 세트 | 409 | 0 (0%) |
| 피싱: 공개 URL 데이터셋 (경로 있음) | 75,643 | 1,721 (2.3%) |
| 피싱: PhiUSIIL (경로 있음) | 28,684 | 757 (2.6%) |

정상 URL을 잘못 잡지 않는 쪽으로 좁게 만든 규칙이라 잡는 비율은 낮다. 최종 점수에는 반영하지 않는다.

### 남은 일: 격리 환경 페이지 분석
페이지 내용이 필요하면 우리 서버가 접속하지 않고 urlscan.io 같은 격리 환경 분석 서비스에 맡긴다. 사용자가 직접 선택할 때만 실행하고, 먼저 기존 검사 결과를 검색하고, 공개(public)가 아닌 설정으로 제출하며, "제3자가 이 주소에 접속한다"는 점을 화면에 밝힌다. urlscan.io 계정과 API 키를 준비한 뒤 구현한다.

## 재현 방법

Python 3.12 + scikit-learn 1.3.2 가상환경에서 저장소 루트 기준으로 실행한다.

```bash
python scripts/build_eval_set.py              # 외부 평가 세트 생성
python scripts/build_training_set.py          # 학습 데이터 생성 (공개 URL 데이터셋을 자동으로 내려받음)
python scripts/train_url_model.py             # 단계별 학습, 최종 모델 저장 (--choose S4 로 직접 선택 가능)
python scripts/build_allowlist.py             # 허용 목록 생성
python scripts/evaluate_model.py              # 새 모델 평가 → evaluation/results/v2/
python scripts/evaluate_model.py --model v1   # 기존 모델 평가 → evaluation/results/v1/
```
